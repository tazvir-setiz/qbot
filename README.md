# ربات برنامهٔ مطالعهٔ قرآن — مُرسِل پیام

ربات تلگرام برای تنظیم و ارسال برنامهٔ مطالعهٔ قرآن به گروه است. مدیر از گفت‌وگوی خصوصی با ربات، گروه مقصد، سوره یا صفحهٔ شروع، ساعت اولین پیام و فاصلهٔ پیام‌ها را تعیین می‌کند. در هر نوبت، پیام معرفی **یک صفحه برای مطالعه** فرستاده می‌شود؛ متن آیات یا تصویر صفحات قرآن در این پروژه دریافت و ارسال نمی‌شود.

پیام مطالعه شامل نام سوره، بازهٔ صفحات آن، صفحهٔ فعلی، شمارهٔ روز و تاریخ شمسی است. پیشرفت، مقصد و زمان ارسال بعدی در SQLite ذخیره می‌شوند. نقطهٔ اجرای پروژه **`main.py`** است.

## ۱. نصب و اجرای محلی

### پیش‌نیازها

- Python نسخهٔ **۳٫۱۱ یا جدیدتر**؛ تصویر Docker پروژه از Python 3.12 استفاده می‌کند.
- توکن ربات ساخته‌شده در BotFather و یک رمز برای ورود به پنل مدیریت.
- دسترسی اینترنت سرور یا رایانه به Telegram API.
- گروهی که بتوانید ربات را به آن اضافه کنید و اجازهٔ ارسال پیام بدهید.
- یک پردازش دائمی: بستن ترمینال، خاموش‌شدن رایانه یا خواب سیستم، اجرای محلی را قطع می‌کند.

برای هر توکن فقط **یک نسخهٔ در حال اجرا** داشته باشید؛ اجرای هم‌زمان روی رایانه و سرور یا چند replica درست نیست.

### ویندوز — PowerShell

فرمان‌ها را در پوشهٔ پروژه اجرا کنید. مسیر مثال را متناسب با محل پروژه تغییر دهید:

```powershell
Set-Location D:\Habib\bot
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
```

اگر Python 3.12 نصب نیست، نسخهٔ نصب‌شدهٔ ۳٫۱۱ یا جدیدتر را در فرمان ساخت محیط جایگزین کنید. اگر `.venv` معتبر از قبل دارید، ساخت مجدد آن لازم نیست. پس از واردکردن تنظیمات و ذخیرهٔ `.env`:

```powershell
.\.venv\Scripts\python.exe -B main.py
```

نیازی به فعال‌سازی محیط با `Activate.ps1` نیست؛ فرمان بالا مستقیم از Python همان محیط استفاده می‌کند. برای توقف عادی در ترمینال `Ctrl+C` بزنید.

### لینوکس — Bash

در پوشهٔ پروژه و با Python سازگار:

```bash
python3 --version
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
[ -f .env ] || cp .env.example .env
nano .env
.venv/bin/python -B main.py
```

اگر ساخت محیط با خطای نبودن `venv` متوقف شد، بستهٔ venv مربوط به نسخهٔ Python را از مدیر سرور یا بسته‌های توزیع خود تهیه کنید. اجرای دائمی روی سرور را طبق راهنمای استقرار انجام دهید.

## ۲. تنظیمات محیط

فایل [.env.example](.env.example) الگوی نصب جدید است. آن را به `.env` در کنار `main.py` کپی و مقدارهای نمونه را جایگزین کنید؛ `.env` موجود را با الگو بازنویسی نکنید.

```dotenv
BOT_TOKEN=YOUR_BOTFATHER_TOKEN
GROUP_ID=
ADMIN_PASSWORD=REPLACE_WITH_A_STRONG_PASSWORD
TIMEZONE=Asia/Tehran
DB_PATH=bot_data.db
SURAH_LIST_FILE=surah_list.txt
ADMIN_USER_IDS=
LOG_LEVEL=INFO
```

مقدارهای توکن و رمز بالا نمونه هستند و باید تغییر کنند.

| متغیر | الزامی / پیش‌فرض | توضیح |
| --- | --- | --- |
| `BOT_TOKEN` | الزامی | توکن کامل دریافتی از BotFather؛ شناسهٔ عددی به‌تنهایی کافی نیست. |
| `ADMIN_PASSWORD` | الزامی | رمز مشترک ورود مدیران در گفت‌وگوی خصوصی با ربات. |
| `GROUP_ID` | اختیاری، خالی | شناسهٔ عددی **منفی** گروه پیش‌فرض. گروه انتخاب‌شده در `/group` برای همان مدیر اولویت دارد. نام کاربری را در این متغیر ننویسید. |
| `ADMIN_USER_IDS` | اختیاری، خالی | شناسه‌های عددی کاربران مجاز، جداشده با کاما؛ برای مثال `123456789,987654321`. نام کاربری پذیرفته نیست. این کاربران نیز باید رمز را وارد کنند. |
| `TIMEZONE` | `Asia/Tehran` | منطقهٔ زمانی ساعت شروع و تاریخ نمایش؛ برای مثال `UTC` نیز قابل استفاده است. |
| `DB_PATH` | `bot_data.db` | مسیر SQLite؛ مسیر نسبی نسبت به پوشهٔ پروژه محاسبه می‌شود. مسیر مطلق هم مجاز است. |
| `SURAH_LIST_FILE` | `surah_list.txt` | فایل اولیهٔ سوره‌ها؛ پس از بارگذاری فهرست سفارشی، نسخهٔ دیتابیس مرجع است. |
| `LOG_LEVEL` | `INFO` | یکی از `DEBUG`، `INFO`، `WARNING`، `ERROR` یا `CRITICAL`. |

اگر `ADMIN_USER_IDS` خالی باشد، هر کسی که رمز را بداند می‌تواند مدیر شود. فهرست مدیران را برای محدودکردن دسترسی تنظیم کنید. هر مدیر مقصد و برنامهٔ مستقل دارد، اما **فهرست سوره‌ها مشترک است و تمام مدیران واردشده می‌توانند آن را تغییر دهند**. نقش جداگانهٔ «مدیر اصلی» وجود ندارد.

قواعد خواندن تنظیمات:

- متغیرهای محیط سیستم یا Variables میزبان بر `.env` اولویت دارند.
- قالب هر خط `KEY=value` است؛ خط خالی و کامنتی که با `#` شروع شود نادیده گرفته می‌شود.
- کوتیشن دور مقدار اختیاری است؛ کامنت را در خط جداگانه بنویسید.
- جایگذاری متغیرها مانند `${NAME}` و مقدار چندخطی پشتیبانی نمی‌شود.
- تغییر تنظیمات محیط نیازمند راه‌اندازی مجدد پردازش است.

`.env` و نسخه‌های پشتیبان آن را منتشر نکنید. فایل اصلی در `.gitignore` قرار دارد؛ این کار فایل‌هایی را که قبلاً وارد Git شده‌اند از تاریخچه حذف نمی‌کند.

## ۳. راه‌اندازی از داخل تلگرام

### ورود و دستورات

۱. ربات را اجرا کنید و گفت‌وگوی **خصوصی** آن را باز کنید.
۲. `/start` را بفرستید و رمز `ADMIN_PASSWORD` را وارد کنید.
۳. پس از ورود، پنل مدیریت نمایش داده می‌شود. مدیریت از داخل گروه انجام نمی‌شود.

| دستور | کاربرد |
| --- | --- |
| `/start` | ورود یا نمایش پنل در صورت ورود قبلی |
| `/menu` | بازگشت به پنل اصلی |
| `/status` | نمایش وضعیت فعلی برنامه |
| `/group` | تنظیم و بررسی گروه مقصد |
| `/cancel` | لغو ورودی یا تأیید در انتظار |
| `/help` | نمایش راهنمای کار با ربات |

بازکردن پنل با `/menu` یا `/status`، ورودی و تأیید در انتظار را لغو می‌کند. `/cancel` برنامهٔ فعال را متوقف نمی‌کند. برای قطع زمان‌بندی از «توقف ارسال» استفاده کنید. «خروج» فقط نشست مدیریت را می‌بندد؛ برنامهٔ فعال ادامه دارد.

پس از پنج رمز اشتباه، ورود همان کاربر برای پنج دقیقه محدود می‌شود. نشست ورود و این محدودیت در حافظه‌اند؛ پس از راه‌اندازی مجدد باید دوباره وارد شوید. ورود مجدد پیشرفت مطالعه را پاک نمی‌کند.

### انتخاب گروه مقصد

۱. ربات را به گروه اضافه کنید.
۲. امکان ارسال متن را برای ربات فراهم کنید. اگر گروه ارسال اعضای عادی را بسته است، دسترسی لازم را بدهید.
۳. در گفت‌وگوی خصوصی `/group` یا «تنظیم گروه» را بزنید.
۴. از دکمهٔ انتخاب گروه تلگرام استفاده کنید؛ این انتخاب‌گر گروه‌هایی را ارائه می‌کند که ربات عضو آن‌هاست. روش دستی نیز با شناسهٔ منفی، مانند `-1001234567890`، یا نام کاربری گروه عمومی، مانند `@your_public_group`، در دسترس است. این‌ها فقط مثال‌اند.
۵. پس از ذخیره، «بررسی دسترسی» و سپس «ارسال آزمایشی» را انجام دهید.
۶. دریافت پیام آزمایشی را در گروه بررسی کنید و سپس برنامهٔ مطالعه را فعال کنید.

لینک دعوت خصوصی ورودی معتبر انتخاب گروه نیست. مقصد باید گروه یا سوپرگروه باشد؛ کانال و گفت‌وگوی خصوصی مقصد این قابلیت نیستند. بررسی دسترسی پیامی به گروه نمی‌فرستد، ولی ارسال آزمایشی واقعاً پیام می‌فرستد و پیشرفت مطالعه را تغییر نمی‌دهد.

ذخیره یا انتخاب دوبارهٔ گروه، برنامهٔ همان مدیر را متوقف می‌کند و زمان ارسال بعدی را پاک می‌کند؛ سوره و صفحه حفظ می‌شوند. پس از بررسی مقصد، دوباره «شروع ارسال» را بزنید. مجوز ارسال متن لزوماً به معنای مجازبودن ارسال همهٔ رسانه‌ها نیست.

## ۴. زمان‌بندی و پیشرفت مطالعه

در «برنامهٔ مطالعه» مراحل زیر را انجام دهید:

۱. «انتخاب سوره» یا «انتخاب صفحه» را بزنید؛ انتخاب سوره، شروع مطالعه را روی ابتدای آن می‌گذارد. اگر صفحه بین چند سوره مشترک باشد، سورهٔ موردنظر را از گزینه‌ها انتخاب کنید.
۲. «دورهٔ ارسال» را تعیین کنید؛ گزینه‌های آمادهٔ هر روز، هر دو روز، هر هفته و هر ساعت وجود دارد.
۳. «ساعت شروع» را انتخاب یا با قالب `HH:MM` وارد کنید؛ برای مثال `09:30`.
۴. در صورت نیاز «شمارهٔ روز» را تغییر دهید؛ مقدار مجاز از ۱ تا ۱٬۰۰۰٬۰۰۰ است.
۵. «پیش‌نمایش» را بررسی کنید.
۶. «شروع ارسال» را بزنید. مقصد و کامل‌بودن تنظیمات هنگام شروع بررسی می‌شوند.

### قالب دوره و معنای ساعت شروع

دورهٔ دستی به ترتیب **روز:ساعت:دقیقه:ثانیه** است:

| مقدار | فاصلهٔ پیام‌ها |
| --- | --- |
| `1:0:0:0` | یک روز |
| `2:0:0:0` | دو روز |
| `0:1:0:0` | یک ساعت |
| `0:0:30:0` | سی دقیقه |

روز بین ۰ تا ۳۶۵۰، ساعت بین ۰ تا ۲۳ و دقیقه و ثانیه بین ۰ تا ۵۹ است. مجموع دوره باید مثبت باشد؛ `0:0:0:0` پذیرفته نیست. ساعت شروع باید بین `00:00` و `23:59` باشد.

اولین پیام در نزدیک‌ترین نوبت آیندهٔ ساعت انتخاب‌شده بر اساس `TIMEZONE` ارسال می‌شود. برای مثال اگر اکنون ساعت ۱۰ باشد و ساعت شروع `09:30` را انتخاب کنید، اولین پیام فردا خواهد بود. **پیام‌های بعدی با فاصلهٔ تعیین‌شده از پایان ارسال قبلی زمان‌بندی می‌شوند**؛ تأخیر شبکه یا توقف سرویس می‌تواند ساعت آن‌ها را جابه‌جا کند. این تنظیم، تضمین ارسال همیشگی در ساعت ثابت دیواری نیست.

«صفحهٔ بعدی» در پنل، صفحه‌ای است که هنوز باید ارسال شود. بعد از ارسال موفق، صفحه جلو می‌رود و شمارهٔ روز یک واحد زیاد می‌شود. بنابراین در دورهٔ ساعتی نیز شمارهٔ روز با هر ارسال افزایش می‌یابد و شمارندهٔ روز تقویمی نیست. پس از پایان صفحات یک سوره، مطالعه از صفحهٔ شروع سورهٔ بعدی در **ترتیب فهرست فعلی** ادامه می‌یابد. صفحهٔ مشترک میان دو سوره برای هر سوره جداگانه معرفی می‌شود.

| تغییر یا عملیات | اثر بر برنامه |
| --- | --- |
| انتخاب سوره یا صفحه | شروع از انتخاب جدید، شمارهٔ روز ۱، پاک‌شدن وضعیت پایان و محاسبهٔ دوبارهٔ زمان شروع در برنامهٔ فعال |
| تغییر دوره یا ساعت | زمان شروع برنامهٔ فعال دوباره محاسبه می‌شود. |
| تغییر شمارهٔ روز | فقط شمارهٔ روز تغییر می‌کند؛ زمان موعد حفظ می‌شود. |
| توقف ارسال | ارسال‌های بعدی متوقف می‌شوند؛ پیشرفت حفظ می‌شود. |
| ویرایش برنامهٔ متوقف | به‌تنهایی برنامه را فعال نمی‌کند؛ «شروع ارسال» لازم است. |
| رسیدن به آخرین صفحهٔ آخرین سوره | وضعیت «پایان‌یافته» ذخیره و برنامه متوقف می‌شود. برای دور جدید سوره یا صفحه را انتخاب کنید. |

دو مدیر می‌توانند برای یک گروه برنامهٔ مستقل بسازند؛ در این حالت پیام‌های هر دو برنامه ارسال می‌شوند. برای جلوگیری از پیام تکراری، برنامه‌های فعال مدیران را هماهنگ کنید.

## ۵. تغییر ترتیب سوره‌ها و صفحات از طریق فایل

### مراحل بارگذاری

۱. وارد «برنامهٔ مطالعه» ← «بارگذاری فهرست سوره‌ها» شوید.
۲. «دریافت فایل فعلی / الگو» را بزنید. این فایل، فهرست واقعاً در حال استفادهٔ ربات است.
۳. فایل را با ویرایشگر متن باز کنید؛ برای تغییر ترتیب، سطرها را جابه‌جا کنید و برای تغییر صفحات، دو عدد هر سطر را ویرایش کنید.
۴. فایل را با پسوند `.txt` و کدگذاری **UTF-8** ذخیره کنید.
۵. در ربات «ارسال فایل جدید» را بزنید و فایل کامل را به‌صورت File/Document ارسال کنید؛ چسباندن متن در پیام کافی نیست.
۶. پیش‌نمایش تعداد سوره‌ها و هشت سطر اول را بررسی کنید و «اعمال فهرست» را بزنید.
۷. پس از ثبت، سوره، صفحه و زمان‌بندی را بررسی و برنامه‌های موردنظر را دوباره فعال کنید.

[نمونهٔ کامل فهرست](docs/surah-list-template.txt) نیز در پروژه موجود است. برای تغییر بعدی، دریافت فایل فعلی از خود ربات مناسب‌تر است؛ نمونهٔ پروژه تغییرات قبلی شما را ندارد.

### قالب و محدودیت‌ها

هر سطر سه بخش دارد که با کاراکتر انگلیسی `|` جدا می‌شوند:

```text
نام سوره|صفحه شروع|صفحه پایان
```

مثال:

```text
# این سه سطر فقط نمونهٔ قالب هستند
فاتحه|1|1
بقره|2|49
آل عمران|50|76
```

**فایل سه‌سطری بالا جایگزین فهرست کامل نیست.** فایل ارسالی باید تمام نام‌های فهرست فعلی را دقیقاً یک بار داشته باشد؛ در حالت عادی ۱۱۴ سوره. حذف، افزودن یا تغییر نام سوره از این مسیر مجاز نیست. نام‌ها را از فایل دریافتی حفظ کنید.

- حجم فایل: از ۱ بایت تا ۶۵٬۵۳۶ بایت، معادل ۶۴ کیلوبایت.
- UTF-8 با BOM یا بدون آن پذیرفته می‌شود؛ فایل Word، Excel یا متن با کدگذاری ANSI پذیرفته نیست.
- شمارهٔ صفحات: ۱ تا ۶۰۴؛ شروع باید کوچک‌تر یا مساوی پایان باشد. اعداد فارسی نیز پذیرفته می‌شوند.
- خط خالی و خط کامنت با `#` نادیده گرفته می‌شود. سطر عنوان ستون‌ها ننویسید.
- نام تکراری، سطر ناقص و صفحهٔ نامعتبر رد می‌شود؛ نام‌ها پس از یکسان‌سازی حروف فارسی/عربی و فاصله‌ها مقایسه می‌شوند.
- اشتراک یا هم‌پوشانی صفحات میان سوره‌ها مجاز است؛ ترتیب سطرها ترتیب مطالعه را تعیین می‌کند.

### اثر تأیید بر مدیران و پیشرفت

فهرست جدید برای **همهٔ مدیران** اعمال می‌شود. پس از تأیید، همهٔ برنامه‌ها متوقف، موعدهای قبلی پاک و وضعیت پایان‌یافته بازنشانی می‌شود. سورهٔ فعلی هر مدیر بر اساس نام تطبیق داده می‌شود؛ جابه‌جایی ردیف‌ها باعث انتخاب سوره‌ای دیگر نمی‌شود.

اگر صفحهٔ فعلی در بازهٔ جدید همان سوره باشد، صفحه و شمارهٔ روز حفظ می‌شوند. در غیر این صورت، صفحه روی شروع جدید و روز روی ۱ قرار می‌گیرد. برای مثال اگر صفحهٔ بعدی ۲۰ باشد و شروع جدید همان سوره ۲۵ شود، ادامه از صفحهٔ ۲۵ و روز ۱ خواهد بود.

تأیید یک‌بارمصرف است و ۱۰ دقیقه اعتبار دارد. لغو، تغییر منو یا راه‌اندازی مجدد، تأیید در انتظار را از بین می‌برد. اگر مدیر دیگری در این فاصله فهرست را تغییر دهد، تأیید نسخهٔ قدیمی اعمال نمی‌شود؛ فایل فعلی را دوباره دریافت کنید. دکمه‌های انتخاب سورهٔ مربوط به نسخهٔ قبلی نیز باید از پنل جدید باز شوند.

فهرست و تطبیق پیشرفت‌ها در یک تراکنش دیتابیس ثبت می‌شوند. اگر نتیجهٔ ارسال قبلی نامشخص باشد، ابتدا باید آن وضعیت بررسی و برطرف شود. پس از بارگذاری موفق، **نسخهٔ دیتابیس بر `SURAH_LIST_FILE` اولویت دارد** و فایل منبع روی دیسک بازنویسی نمی‌شود. برای تغییر فهرست در نصب دارای پیشرفت، از همین مسیر تلگرام استفاده کنید؛ جابه‌جایی دستی سطرهای فایل اولیه می‌تواند موقعیت‌های ذخیره‌شده را نامتناسب کند.

<a id="messages"></a>

## ۶. ارسال پیام دلخواه و رابط کاربری

از «ارسال پیام» استفاده کنید، پیام یا رسانه را بفرستید و پس از بررسی مقصد، تأیید کنید. متن، عکس، ویدئو، انیمیشن، استیکر، فایل صوتی، پیام صوتی، سند، پیام ویدئویی، مخاطب و موقعیت مکانی پشتیبانی می‌شوند. آلبوم را به‌صورت رسانه‌های تکی بفرستید؛ ارسال آلبوم و نظرسنجی در این مسیر پشتیبانی نمی‌شود.

تأیید ارسال دلخواه یک‌بارمصرف و دارای اعتبار ۱۰ دقیقه است. تغییر مقصد یا خروج از جریان تأیید، آن را لغو می‌کند. ارسال دلخواه، پیام آزمایشی و پیش‌نمایش، پیشرفت مطالعه را جلو نمی‌برند. اگر ارسال با خطای مبهم شبکه روبه‌رو شد، پیش از تلاش مجدد گروه را بررسی کنید؛ ممکن است پیام رسیده ولی پاسخ تلگرام دریافت نشده باشد.

پنل، وضعیت فعالیت، صفحهٔ بعدی، پیشرفت سوره، مقصد، آخرین ارسال و موعد بعدی را نشان می‌دهد. انتخاب سوره صفحه‌بندی و جست‌وجوی نام دارد. پیش‌نمایش فقط در خصوصی و با تاریخ امروز نمایش داده می‌شود. برای متن‌های حداکثر ۲۵۶ کاراکتری دکمهٔ کپی فراهم است. دکمه‌های رنگی و راهنمای جمع‌شونده در کد استفاده شده‌اند؛ ظاهر آن‌ها به پشتیبانی نسخهٔ تلگرام کاربر بستگی دارد.

<a id="persistence"></a>

## ۷. اطلاعات ذخیره‌شده و رفتار هنگام خطا

SQLite هنگام اولین اجرای واقعی ساخته می‌شود؛ نیازی به ساخت دستی یا ارسال دیتابیس خالی همراه پروژه نیست. اطلاعات زیر در آن می‌مانند:

- مقصد، سوره، صفحه، شمارهٔ روز و تنظیمات زمان‌بندی هر مدیر؛
- وضعیت فعال، پایان مطالعه، زمان ارسال بعدی، آخرین ارسال و آخرین خطای ذخیره‌شده؛
- نشانگر ارسال در جریان و فهرست سفارشی سوره‌ها.

رمز و توکن از محیط خوانده می‌شوند. نشست ورود، ورودی نیمه‌کاره و تأییدهای در انتظار در حافظه‌اند و با ری‌استارت باقی نمی‌مانند.

| وضعیت | رفتار ربات و اقدام مدیر |
| --- | --- |
| راه‌اندازی مجدد عادی | برنامه‌های فعال از اطلاعات ذخیره‌شده ادامه پیدا می‌کنند؛ ورود مجدد به پنل لازم است. |
| عقب‌افتادن موعد هنگام خاموشی | حداکثر یک پیام عقب‌افتاده ارسال می‌شود و ادامه طبق دوره خواهد بود؛ پیام‌های تمام روزهای غیبت پشت‌سرهم ارسال نمی‌شوند. |
| خطای موقت شبکه | بدون جلو بردن صفحه، معمولاً پس از ۶۰ ثانیه تلاش مجدد می‌شود. محدودیت سرعت تلگرام طبق زمان اعلام‌شدهٔ آن رعایت می‌شود. |
| رد دائمی ارسال، مانند حذف دسترسی | برنامه متوقف و خطا ثبت می‌شود؛ در صورت امکان مدیر مطلع می‌شود. پس از اصلاح مقصد، شروع مجدد لازم است. |
| تبدیل گروه به سوپرگروه | اگر تلگرام شناسهٔ جدید را اعلام کند، آن شناسه ذخیره و ارسال یک بار با مقصد جدید تکرار می‌شود. |
| خطای ثبت SQLite پس از ارسال موفق | نتیجه در حافظه نگه داشته می‌شود؛ هر ۳۰ ثانیه فقط ثبت اطلاعات دوباره امتحان می‌شود. |
| قطع پردازش وسط ارسال یا ثبت نتیجه | نشانگر پایدار مانع ادامهٔ خودکار می‌شود؛ گروه را بررسی و سوره/صفحهٔ صحیح بعدی را انتخاب کنید. |

اگر پاسخ شبکه پس از تحویل پیام گم شود، احتمال ارسال تکراری در تلاش مجدد وجود دارد؛ تضمین «دقیقاً یک بار» وجود ندارد. همچنین این پروژه برای چند پردازش هم‌زمان با یک توکن طراحی نشده است.

<a id="deployment"></a>

## ۸. اجرای دائمی روی سرور

این برنامه از **long polling** استفاده می‌کند و سرویس HTTP نیست. برای اجرای آن دامنه، پورت وب، `PORT` یا مسیر webhook لازم نیست.

### Railway

[راهنمای فارسی و مرحله‌به‌مرحلهٔ Railway](docs/railway-fa.md) را دنبال کنید. فایل‌های `Dockerfile`، `railway.json` و `.dockerignore` آماده‌اند. تنظیمات ضروری استقرار:

- توکن و رمز را در Variables سرویس وارد کنید.
- یک Volume پایدار روی `/data` متصل و `DB_PATH=/data/bot_data.db` را تنظیم کنید.
- یک replica در یک region داشته باشید و خواب خودکار سرویس را غیرفعال کنید.
- نسخهٔ محلی یا سرور قبلی را پیش از فعال‌کردن سرویس متوقف کنید.

`railway.json` به‌تنهایی Volume ایجاد نمی‌کند. بدون ذخیره‌سازی پایدار، پیشرفت و فهرست سفارشی در استقرار بعدی ممکن است از دست بروند.

### cPanel

[راهنمای فارسی و مرحله‌به‌مرحلهٔ cPanel](docs/cpanel-fa.md) شامل آماده‌سازی Python، مسیرها، Cron، لاگ و توقف پردازش است. هاست باید اجرای پردازش دائمی Python، دسترسی خروجی به تلگرام و قفل فایل لینوکسی را مجاز بداند. داشتن گزینهٔ Setup Python App یا Passenger به‌تنهایی کافی نیست.

فایل `deploy/cpanel_worker.py` برای اجرای لینوکسی، قفل جلوگیری از اجرای هم‌زمان، ثبت PID و چرخش لاگ آماده شده است. فایل‌های پروژه و `.env` را خارج از `public_html` و ریشهٔ وب تمام دامنه‌ها نگه دارید. مسیرهای نمونهٔ راهنما را با نام کاربری واقعی هاست جایگزین کنید.

<a id="backup"></a>

## ۹. پشتیبان‌گیری، بازیابی و به‌روزرسانی

### ساخت پشتیبان سازگار

پس از ایجاد دیتابیس، ابزار زیر با API پشتیبان SQLite نسخهٔ سازگار می‌سازد و صحت ساختاری آن را بررسی می‌کند. این روش هنگام اجرای ربات نیز قابل استفاده است؛ کپی سادهٔ فایل اصلی دیتابیس در حال اجرا ممکن است داده‌های WAL را جا بگذارد.

ویندوز:

```powershell
.\.venv\Scripts\python.exe -B scripts\backup_db.py backups\before-update-01.db
```

لینوکس:

```bash
.venv/bin/python -B scripts/backup_db.py backups/before-update-01.db
```

در این حالت مبدأ از `DB_PATH` خوانده می‌شود و تنظیمات محیط باید معتبر باشند. برای تعیین مبدأ مستقل از تنظیمات:

```bash
.venv/bin/python -B scripts/backup_db.py backups/manual-01.db --source bot_data.db
```

نام مقصد هر پشتیبان باید جدید باشد؛ ابزار فایل موجود را بازنویسی نمی‌کند. مسیرهای آرگومان فرمان نسبت به پوشهٔ جاری‌اند. نسخه‌ای از پشتیبان را خارج از سرور نگه دارید. این فایل شامل فهرست سفارشی، مقصدها و پیشرفت است؛ `.env` را شامل نمی‌شود و تنظیمات محیط باید جداگانه و امن نگهداری شوند.

### بازیابی

۱. همهٔ پردازش‌های ربات و راه‌انداز خودکار، مانند Cron، را متوقف کنید.
۲. از وضعیت فعلی پشتیبان بگیرید؛ فایل‌های موجود دیتابیس و فایل‌های همراه `-wal` و `-shm` را بدون دورریختن نگه دارید.
۳. فایل پشتیبان انتخابی را در مسیر واقعی `DB_PATH` جایگزین کنید. فایل‌های WAL/SHM دیتابیس قبلی نباید کنار نسخهٔ بازیابی‌شده باقی بمانند؛ فقط پس از اطمینان از بسته‌بودن همهٔ اتصال‌ها آن‌ها را همراه نسخهٔ قبلی به محل نگهداری منتقل کنید.
۴. دسترسی خواندن و نوشتن پردازش به فایل و پوشهٔ والد را بررسی کنید.
۵. تنها یک نمونه را اجرا کنید و وضعیت و آخرین پیام گروه را بررسی کنید. پشتیبان ممکن است برنامهٔ فعال با موعد گذشته داشته باشد و پس از اجرا یک پیام عقب‌افتاده ارسال کند.

جزئیات مسیرها و توقف راه‌انداز هر میزبان در راهنمای همان میزبان آمده است. بازیابی نسخهٔ قدیمی، پیشرفت را نیز به همان تاریخ برمی‌گرداند.

### به‌روزرسانی کد

پیش از به‌روزرسانی پشتیبان بگیرید، ربات را متوقف کنید، کد جدید را دریافت و وابستگی‌های `requirements.txt` را با Python همان محیط نصب کنید. `.env`، دیتابیس و Volume را حفظ کنید. سپس تست‌ها را اجرا و فقط یک نمونه را راه‌اندازی کنید. مهاجرت‌های افزایشی دیتابیس هنگام شروع انجام می‌شوند؛ برای ارتقا دیتابیس را حذف نکنید.

### فایل‌های تولیدشده

| فایل یا پوشه | امکان پاک‌سازی |
| --- | --- |
| `__pycache__/`، `*.pyc`، `.pytest_cache/` | قابل تولید مجدد؛ حذف آن‌ها تنظیمات ربات را پاک نمی‌کند. |
| `logs/` | سابقهٔ خطاها از دست می‌رود؛ پاک‌سازی را با پردازش متوقف انجام دهید. |
| `run/` | اطلاعات و قفل راه‌انداز cPanel؛ هنگام اجرای worker پاک نکنید. |
| `.venv/` | قابل ساخت مجدد با نصب وابستگی‌ها؛ حذف آن محیط اجرا را از بین می‌برد. |
| `bot_data.db` یا مسیر `DB_PATH` و فایل‌های همراه | دادهٔ عملیاتی است؛ حذف آن مقصدها، پیشرفت و فهرست سفارشی را از بین می‌برد. |
| `.env` و `backups/` | تنظیمات خصوصی و راه بازیابی؛ فایل موقت محسوب نمی‌شوند. |

## ۱۰. رفع خطاهای رایج

| نشانه یا خطا | بررسی و راه‌حل |
| --- | --- |
| `Unresolved reference 'telegram'` در ویرایشگر | Interpreter پروژه را روی `.venv/Scripts/python.exe` در ویندوز یا `.venv/bin/python` در لینوکس بگذارید و `pip install -r requirements.txt` را با همان Python اجرا کنید. وابستگی پروژه `python-telegram-bot` است. |
| `ModuleNotFoundError: telegram` | اجرای برنامه و نصب وابستگی‌ها با دو Python متفاوت را بررسی کنید؛ از مسیر کامل Python محیط مجازی استفاده کنید. |
| `Missing required setting` | `.env` کنار `main.py` و مقدار `BOT_TOKEN` و `ADMIN_PASSWORD` را بررسی کنید؛ در سرور Variables را نیز ببینید. |
| `Invalid BOT_TOKEN format` یا رد توکن توسط تلگرام | توکن کامل BotFather را جایگزین مقدار نمونه کنید؛ مقدار متغیر محیط سیستم می‌تواند `.env` را پوشانده باشد. |
| `Conflict` در polling | نسخهٔ دیگر همین ربات را روی رایانه، Railway، cPanel یا ترمینال دیگر متوقف کنید؛ فقط یک پردازش باقی بماند. |
| ربات در گروه به دستور مدیریت پاسخ نمی‌دهد | پنل مدیریت در خصوصی است؛ `/start` را در گفت‌وگوی خصوصی بفرستید. |
| ورود ممکن نیست | رمز و `ADMIN_USER_IDS` را بررسی کنید؛ محدودیت پنج‌دقیقه‌ای پس از پنج رمز اشتباه را در نظر بگیرید. |
| `Chat not found` | ربات را عضو گروه کنید و مقصد را با `/group` دوباره انتخاب کنید؛ شناسه یا نام کاربری ممکن است اشتباه باشد. |
| `Forbidden` یا نبودن اجازهٔ ارسال | عضویت و دسترسی متن/رسانه را بررسی، پیام آزمایشی ارسال و برنامه را دوباره فعال کنید. |
| برنامه تنظیم شده ولی پیام نمی‌فرستد | وضعیت «فعال»، مقصد، موعد بعدی، منطقهٔ زمانی و روشن‌بودن پردازش را ببینید؛ تنظیم گزینه‌ها به‌تنهایی برنامه را شروع نمی‌کند. |
| پیام اول تا فردا ارسال نمی‌شود | اگر ساعت انتخابی امروز گذشته باشد، نزدیک‌ترین نوبت آینده فرداست. |
| برنامه پس از تغییر گروه یا فایل متوقف است | رفتار مورد انتظار است؛ وضعیت را بررسی و «شروع ارسال» را بزنید. |
| نتیجهٔ ارسال قبلی نامشخص است | پیام‌های گروه را بررسی کنید، سوره/صفحهٔ صحیح بعدی را انتخاب و سپس برنامه را فعال کنید. |
| وضعیت «پایان‌یافته» اجازهٔ ادامه نمی‌دهد | برای دور بعد سوره یا صفحهٔ شروع جدید انتخاب کنید. |
| تغییر `surah_list.txt` اثری ندارد | فهرست سفارشی دیتابیس اولویت دارد؛ از بارگذاری فایل داخل تلگرام استفاده کنید. |
| فایل فهرست رد می‌شود | فایل فعلی را دریافت و کامل ویرایش کنید؛ UTF-8، پسوند TXT، حجم، نام‌های کامل و بازهٔ ۱ تا ۶۰۴ را بررسی کنید. |
| تأیید یا دکمهٔ قدیمی کار نمی‌کند | پنل تازه باز کنید؛ مهلت تأیید یا نسخهٔ فهرست ممکن است تغییر کرده باشد. |
| SQLite قفل است یا قابل نوشتن نیست | پردازش‌های اضافی، مجوز پوشه، فضای دیسک و مسیر Volume را بررسی کنید؛ هنگام بازیابی ثبت اطلاعات، پیام را دستی دوباره نفرستید. |
| اطلاعات بعد از Deploy ناپدید می‌شود | اتصال Volume و تطابق `DB_PATH` با مسیر آن را بررسی کنید. |

اجرای مستقیم، لاگ را در خروجی ترمینال می‌نویسد. Railway لاگ سرویس را نمایش می‌دهد و راه‌انداز cPanel در `logs/` فایل چرخشی می‌سازد. حتی در سطح `DEBUG`، لاگ داخلی کتابخانه‌های تلگرام و HTTP روی `WARNING` محدود شده تا جزئیات حساس پیام ورود ثبت نشود. هنگام فرستادن خطا برای بررسی، توکن، رمز و اطلاعات خصوصی را از متن حذف کنید.

### اجرای تست‌ها

ویندوز:

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -v
```

لینوکس:

```bash
.venv/bin/python -B -m unittest discover -s tests -v
```

تست‌ها از دیتابیس موقت و بات ساختگی استفاده می‌کنند؛ به تلگرام پیام واقعی نمی‌فرستند و دیتابیس اصلی را تغییر نمی‌دهند. گزینهٔ `-B` از تولید فایل‌های بایت‌کد جلوگیری می‌کند. تست‌های خودکار جای بررسی عضویت و مجوز گروه روی سرویس واقعی را نمی‌گیرند؛ پس از استقرار، ارسال آزمایشی و وضعیت برنامه را نیز بررسی کنید.


## 🤖 دستیار هوش مصنوعی داخل گروه

در پنل اصلی گزینهٔ **«🤖 دستیار AI»** اضافه شده است. این قابلیت مستقل از برنامهٔ ارسال روزانه است و به‌صورت پیش‌فرض خاموش می‌ماند.

راه‌اندازی:

1. ابتدا از «تنظیم گروه» گروه مقصد را انتخاب کنید.
2. وارد «دستیار AI» شوید.
3. API Endpoint یک سرویس سازگار با OpenAI Chat Completions را وارد کنید.
4. API Key و نام دقیق Model را ثبت کنید.
5. در صورت نیاز، «شخصیت / پرامپت» را برای لحن و قواعد پاسخ تنظیم کنید.
6. برای پاسخ‌های رسانه‌ای، از «افزودن عکس/GIF/استیکر» رسانه‌ها را ثبت کنید و برای عکس یا GIF در کپشن توضیح دهید چه زمانی مناسب است.
7. AI را فعال کنید.

پس از فعال‌سازی، بات فقط در همان گروه تنظیم‌شده و فقط در این حالت‌ها پاسخ می‌دهد:

- کاربر بات را با @username منشن کند و سؤال بپرسد.
- کاربر روی یکی از پیام‌های قبلی بات Reply کند.

پاسخ مستقیماً به همان پیام ارسال می‌شود. AI می‌تواند از کتابخانهٔ رسانه‌ای ثبت‌شده، عکس، GIF یا استیکر مناسب را انتخاب کند. برای جلوگیری از اسپم، برای هر کاربر یک محدودیت کوتاه بین درخواست‌های متوالی وجود دارد و حافظهٔ مکالمه نیز کوتاه و درون‌حافظه‌ای است.

> کلید API در پنل نمایش داده نمی‌شود و پیام حاوی کلید پس از ثبت، در صورت داشتن مجوز لازم حذف می‌شود. مقدار کلید در SQLite ذخیره می‌شود؛ از فایل دیتابیس و نسخه‌های پشتیبان آن محافظت کنید.
